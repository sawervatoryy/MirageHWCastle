**«Изумрудная волна»** — аналог «Золотой лихорадки» на HolyWorld. Всё настраивается через `config.yml`,
`lang.yml` и команды, без правки кода.

## Что внутри

- **Замок** на координатах **1000 / 1000** (меняется в `config.yml`): запрет строительства и приватов, PvP всегда включён.
- **Шалкеры трёх редкостей** (Обычный / Редкий / Эпический) + ивентовый **Изумрудный**. Новые уровни создаются командой.
- **Привязка блоков**: смотрите на блок и введите `/hwcastle bind` — блок становится «точкой» шалкера. Шалкеры появляются на привязанных блоках **случайно**, редкость выбирается по весам.
- **Принудительный спавн** шалкеров командой, очистка, список точек.
- **GUI лута** для каждого типа шалкера: кладёте предметы в окно, шанс меняется кликом.
- **Ивент «Изумрудная волна»**: все шалкеры становятся зелёными, ломаются 16 раз, лут умножается, часть шалкеров пуста и взрывается. Запуск командой или по расписанию, босс-бар, титры, предупреждения, команды при старте/конце.
- **Вставка замка из схематики** `zamok.schem` без WorldEdit (по частям, без лагов).
- Полная кастомизация сообщений (`lang.yml`) и поведения (`config.yml`), цвета `&f` / `&#00ACFF`, HEX и скобки `« » ‹ › ⌈ ⌋`.

## Сборка и установка

```bash
mvn clean package
# результат: target/MirageHWCastle-0.1-Pre-Release.jar
```

1. Положите jar в `plugins/`.
2. Запустите сервер — создадутся `config.yml`, `lang.yml`, `levels.yml`.
3. Положите схематику замка в `plugins/MirageHWCastle/zamok.schem` (если хотите вставлять замок командой).
4. Настройте `castle.world` и координаты в `config.yml`, выполните `/hwcastle reload`.

## Быстрый старт

1. Вставьте замок: `/hwcastle paste` (или постройте сами / вставьте через WorldEdit).
2. Встаньте у блока, где должен появляться шалкер (например, резной каменный кирпич), посмотрите на него и введите:
   ```
   /hwcastle bind            — случайная редкость при каждом появлении
   /hwcastle bind epic       — на этом блоке всегда эпический
   ```
   Шалкер появится сразу (`spawn.spawn-on-bind`). После поломки блок вернётся к исходному виду.
3. Повторите для всех мест (в оригинале — 16 точек).
4. Настройте лут: `/hwcastle loot`.
5. Проверьте ивент: `/hwcastle event start 120`.

## Как это работает

- **Привязанный блок** хранится вместе со своим исходным `BlockData`. Когда шалкер должен появиться, блок заменяется на шалкер-бокс нужного цвета, над ним создаётся голограмма с остатком ударов. Когда шалкер сломан (или исчез), возвращается исходный блок.
- **Появление**: раз в случайное время между `spawn.min-interval-seconds` и `spawn.max-interval-seconds` (по умолчанию 60–90 с) на `spawn.per-cycle` свободных точек появляются новые шалкеры. Спавн идёт только в **загруженных чанках**.
- **Редкость** выбирается по «весу» уровня (`/hwcastle level set <id> weight <N>`), если точка привязана как `random`.
- **Удар** — ЛКМ по шалкеру (режим `hits.mode: CLICK`) или попытка сломать блок (`BREAK`). Шалкер нельзя открыть, сломать «по-настоящему», взорвать или сдвинуть поршнем.
- **Успех / неудача**: после последнего удара бросается шанс «пустого» (`fail-chance` уровня). Успех — лут выпадает предметами на землю, их может забрать любой. Неудача — взрыв: урон всем игрокам в радиусе, блоки не ломаются.
- **Сбой сервера**: если после краша на точке остался шалкер, он автоматически заменяется исходным блоком при загрузке чанка.

## Редкости шалкеров

| Редкость | Цвет | Ударов | Вес по умолчанию |
|---|---|---|---|
| Обычный (`common`) | Серый | 5 | 60 |
| Редкий (`rare`) | Голубой | 7 | 30 |
| Эпический (`epic`) | Фиолетовый | 12 | 10 |
| Изумрудный (`emerald`, ивент) | Зелёный | 16 | — (только в ивенте) |

Свои уровни:

```
/hwcastle level create <id> <удары> <цвет> [вес]
/hwcastle level set <id> name &#FFAA00Легендарный
/hwcastle level set <id> color orange
/hwcastle level set <id> hits 20
/hwcastle level set <id> weight 5
/hwcastle level set <id> fail 25        — шанс пустого, %
/hwcastle level set <id> min 1          — минимум предметов за шалкер
/hwcastle level set <id> max 5          — максимум (0 — без лимита)
/hwcastle level delete <id>
```

Цвет — любое имя `DyeColor` (`gray`, `light_blue`, `purple`, `green`, `orange`...).

## Изумрудная волна

Серверный ивент, проходящий в замке (`1000 / 1000`).

- **Старт**: все стоящие шалкеры превращаются в изумрудные; если `event.fill-all-points: true`, изумрудные шалкеры появляются на **всех** привязанных блоках.
- **Механика**: каждый изумрудный шалкер нужно ударить `event.hits-to-break` раз (по умолчанию **16**). Содержимое есть не в каждом: шанс пустого — `event.fail-chance` (по умолчанию **40 %**).
- **Успех**: выпадает лут уровня `emerald` × `event.loot-multiplier`. Забрать может любой игрок рядом.
- **Неудача**: шалкер взрывается и наносит урон всем в `event.explosion.radius`.
- **Пополнение** шалкеров идёт каждые `event.spawn-interval-seconds` секунд.
- **Конец**: изумрудные шалкеры исчезают, возобновляется обычный спавн.

Всё настраивается в `config.yml → event` (длительность, число ударов, шансы, множитель лута, взрыв, босс-бар, титры, звуки, частицы, предупреждения, расписание, команды старта и конца) и в `lang.yml → event`.

```
/hwcastle event start [секунды]   — запустить (секунды необязательны)
/hwcastle event stop              — остановить
/hwcastle event status            — состояние
```

Автозапуск:

```yaml
event:
  schedule:
    enabled: true
    timezone: Europe/Moscow
    times: ["19:00", "22:00"]
    days: [FRIDAY, SATURDAY]     # пусто — каждый день
```

Лут изумрудного шалкера редактируется как у любого уровня: `/hwcastle loot emerald`.

## Замок и защита

Для зоны замка (`castle.center-x/z`, `castle.radius`, `castle.min-y/max-y`):

- запрещены установка/разрушение блоков и жидкости (`castle.protection.deny-build`);
- запрещены команды приватов из списка `castle.protection.blocked-commands`;
- PvP всегда включён (`castle.protection.force-pvp`) — урон между игроками, отменённый другими плагинами, возвращается.

Обход — право `miragehwcastle.bypass`.

> Защита от **приватов** работает через блокировку команд. Если у вас плагин регионов с другим набором команд — добавьте их в `blocked-commands` или запретите создание регионов в зоне замка средствами самого плагина регионов.

### Вставка замка из схематики

```
/hwcastle paste [мир] [y]
```

Читает `plugins/MirageHWCastle/zamok.schem` (формат Sponge `.schem` v2/v3), центрирует по `castle.center-x/z` и ставит блоки порциями (`castle.schematic.blocks-per-tick`). Чтение файла идёт в отдельном потоке, на главный поток ложится только установка блоков. Блок-сущности (сундуки, таблички) не переносятся.

## Команды

Основная команда `/hwcastle`, алиасы `/hwc`, `/castle`.

| Команда | Описание |
|---|---|
| `/hwcastle bind [уровень\|random]` | Привязать блок, на который вы смотрите |
| `/hwcastle unbind` | Отвязать блок (шалкер на нём убирается) |
| `/hwcastle points` | Список привязанных блоков |
| `/hwcastle spawn [уровень\|random] [число\|all]` | Принудительный спавн на свободных точках |
| `/hwcastle clear` | Убрать все шалкеры |
| `/hwcastle level list` / `info <id>` | Просмотр уровней |
| `/hwcastle level create <id> <удары> <цвет> [вес]` | Создать уровень |
| `/hwcastle level set <id> <поле> <значение>` | Изменить уровень (`name`, `color`, `hits`, `weight`, `fail`, `min`, `max`) |
| `/hwcastle level delete <id>` | Удалить уровень |
| `/hwcastle loot [уровень]` | GUI лута |
| `/hwcastle event start [секунды]` / `stop` / `status` | Ивент «Изумрудная волна» |
| `/hwcastle paste [мир] [y]` | Вставить замок из схематики |
| `/hwcastle reload` | Перезагрузить `config.yml` и `lang.yml` |
| `/hwcastle about` | О плагине |

## GUI лута

`/hwcastle loot` — выбор уровня, `/hwcastle loot <id>` — сразу редактор.

- В верхние **45 слотов** кладутся предметы — они становятся лутом уровня.
- **Shift + ЛКМ** по предмету — шанс **+5 %**, **Shift + ПКМ** — **−5 %** (от 1 до 100 %). Новый предмет получает шанс `loot.default-chance`.
- Забрали предмет из окна — он убран из лута.
- Лут сохраняется при **закрытии окна** (запись на диск — асинхронно). Кнопка «Назад» возвращает к выбору уровня.

Как выпадает лут: каждая позиция проверяется по своему шансу независимо, затем применяются `min-items` / `max-items` уровня. Предметы сохраняют все свои данные (название, чары, NBT-компоненты).

## Настройка config.yml

Файл подробно прокомментирован. Основные блоки:

| Блок | Что настраивается |
|---|---|
| `castle` | Мир, центр, размер зоны, защита, команды-запреты, параметры схематики |
| `spawn` | Интервал циклов, число шалкеров за цикл, заполнение при старте |
| `hits` | Режим удара (`CLICK` / `BREAK`), пауза, звуки и частицы ударов/поломки/появления |
| `hologram` | Включение и высота голограммы |
| `fail-explosion` | Радиус, урон и эффекты взрыва пустого обычного шалкера |
| `loot` | Шанс нового предмета по умолчанию |
| `event` | Вся «Изумрудная волна» |

Звуки задаются ключом (`"minecraft:entity.generic.explode"`), частицы — именем (`EXPLOSION`, `CRIT`, `HAPPY_VILLAGER`, `END_ROD`).

## Настройка lang.yml

- Основной цвет текста — `&f`, выделение — `&#00ACFF`. Работают `&`-коды и HEX `&#RRGGBB`.
- `{prefix}` подставляет префикс. Список строк = несколько строк в чате.
- Плейсхолдеры указаны в именах/примерах сообщений, например `{name}`, `{left}`, `{max}`, `{time}`, `{x}`, `{z}`, `{hits}`.
- Формат голограммы: `hologram.format`, `\n` — перенос строки.

## Структура проекта

```
ru.miragestudio.hwcastle
├── MirageHWCastle            — главный класс, сборка компонентов
├── command/HwCastleCommand   — команды и автодополнение
├── config/                   — Settings (снимок config.yml), Lang, FxSpec, DataStore, DefaultLevels
├── model/                    — ShulkerLevel, ShulkerPoint, ActiveShulker, LootEntry
├── manager/                  — ShulkerManager, EventManager, LevelRegistry, PointRegistry, LootService
├── gui/LootGui               — выбор уровня и редактор лута
├── listener/                 — ShulkerListener, CastleListener
├── castle/                   — SchematicPaster, Nbt (чтение .schem)
└── util/                     — Text, Brand, ConfigFiles
```

Принципы: ответственность разделена по классам; `Settings` — неизменяемый снимок, подменяемый целиком (`volatile`); уровни и точки хранятся в потокобезопасных реестрах; запись `levels.yml` / `points.yml` и чтение схематики идут вне главного потока, обращение к миру — только в главном; внешних библиотек нет (при их появлении подключайте через `libraries` в `plugin.yml`).

## Известные ограничения

- Folia не поддерживается.
- Шалкеры появляются только в **загруженных чанках**; на выгруженных точках спавн пропускается до загрузки.
- Блок-сущности схематики (сундуки, таблички, головы) не вставляются.
- Изменения `levels.yml` вручную не подхватываются на лету — используйте команды и GUI.
- Изменения цвета/ударов уровня применяются к уже стоящим шалкерам после их респавна.
